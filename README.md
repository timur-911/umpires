# UMPIR.ES

Справочник международных судей по настольному теннису: профили судей, бейджи
(White / Blue / Gold), страны и ассоциации, турниры, карта и графы связей.

Сайт — одна статическая страница (`index.html`), без сборки. Живая часть
(вход, заявки от судей, файлы, раздел «Заявки» для куратора) работает на
Supabase. Язык по умолчанию — английский; выбор RU/EN запоминается в браузере.

## Файлы

| Файл | Зачем |
| --- | --- |
| `index.html` | весь сайт: вёрстка, данные и логика |
| `config.js` | URL и anon key проекта Supabase — единственное, что нужно заполнить |
| `supabase/migrations/` | схема базы, политики доступа и бакет для файлов |
| `supabase/config.toml` | конфигурация проекта для Supabase CLI и интеграции с GitHub |
| `.nojekyll` | отключает обработку Jekyll на GitHub Pages |

## Публикация на GitHub Pages

1. Файлы лежат в корне ветки `main`.
2. Settings → Pages: Source = **Deploy from a branch**, Branch = **main**,
   папка **/ (root)**.
3. Через 1–2 минуты сайт открыт на `https://timur-911.github.io/umpires/`.

Без заполненного `config.js` сайт работает как статический справочник: поиск,
профили, страны, турниры, карта, граф, RU/EN и тёмная тема. Кнопка «Войти»
скрыта, отправка заявок отключена.

## Подключение Supabase

1. **Проект.** supabase.com → New project. Регион ближе к пользователям.
2. **Схема.** SQL Editor → New query → вставить весь
   `supabase/migrations/20261111000000_init.sql` → Run. Создаются таблицы
   `submissions`, `approved`, `editors`, `profiles`, приватный бакет
   `uploads` и политики RLS. Повторный запуск безопасен.

   Либо, вместо ручного запуска, подключить репозиторий: Project Settings →
   Integrations → GitHub → Authorize, выбрать `timur-911/umpires`, в поле
   пути к папке `supabase/` указать `.` и включить *Deploy to production*.
   Тогда миграции применяются сами при пуше в `main`. Интеграция доступна на
   бесплатном плане; отдельные базы под pull request (branching) — только на
   Pro. Достаточно чего-то одного: если схему уже прогнали руками, интеграция
   не нужна.
3. **Ключи.** Settings → API → скопировать *Project URL* и *anon public* в
   `config.js`. Оба значения публичные: anon key рассчитан на то, чтобы лежать
   в коде сайта, данные закрывают политики RLS.
4. **Адреса возврата.** Authentication → URL Configuration:
   Site URL = `https://timur-911.github.io/umpires/`,
   в Redirect URLs добавить его же (и `http://localhost:*`, если проверяете
   локально). Без этого ссылка из письма не вернёт на сайт.
5. **Куратор.** Войдите на сайте по ссылке из письма, затем в SQL Editor:

   ```sql
   insert into public.editors (uid, note)
   select id, 'curator' from auth.users where email = 'tkhojayev@gmail.com'
   on conflict (uid) do nothing;
   ```

   После этого в подвале появится ссылка «Заявки» — очередь на проверку.

Письма для входа по умолчанию шлёт служебный SMTP Supabase с жёстким лимитом
(несколько писем в час) — он годится для проверки. Для реальной работы
подключите свой SMTP в Authentication → Emails.

## Как устроена живая часть

Вход — ссылка на email (magic link, PKCE), паролей нет.

| Таблица | Что хранит | Кто видит |
| --- | --- | --- |
| `submissions` | заявки: «я работал на этом турнире», загруженные списки местных судей | автор — свои, куратор — все |
| `approved` | принятые записи «я работал» | все, включая незалогиненных |
| `editors` | uid кураторов | вошедшие |
| `profiles` | имя вместо uid в разделе «Заявки» | все |

Файлы заявок (PDF, CSV, TXT, JPG, PNG) идут в приватный бакет `uploads`, в
папку по uid автора; в заявке хранится ссылка со сроком год. Открыть файл
может автор и куратор.

Страницы турниров и «Заявки» обновляются сразу через Supabase Realtime —
для этого миграция добавляет обе таблицы в публикацию
`supabase_realtime`.

В коде вся работа с Supabase собрана в один блок (поиск по `supaDb`) и
закрыта небольшим слоем с методами `collection()` / `doc()`, поэтому остальные
части страницы не знают, какая под ними база.

## Данные

Справочная часть вшита в `index.html` в объект `DATA`: активные международные
судьи, Blue/Gold Badge, участники Олимпийских и Паралимпийских игр, турниры.
Источники указаны в подвале соответствующих разделов.
